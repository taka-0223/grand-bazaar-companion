# 風のグランドバザール 作戦ボード

個人利用を前提にした PWA です。種・料理・計画をつなぎ、既知情報だけを使って次の行動を逆算します。

## 保存
- IndexedDB を主保存、localStorage をミラーとして使用
- アプリのバージョン更新とプレイヤーデータを分離
- JSON バックアップ/復元に対応
- プレイヤーデータはこのリポジトリには含めません

## 公開
GitHub Pages の `main` ブランチ直下から配信する構成です。

## Third-party data
一部のゲームデータは MIT ライセンスの公開データを利用しています。詳細は `THIRD_PARTY_NOTICES.md` を参照してください。

## Masterの起動時軽量化
- `data/board-master.full.v1.json` は完全版Masterの正本です。加工・経済計算・整合性テストはここを参照します。
- `index.html` の `MASTER_DATA` は、現在のUIが参照する項目だけをビルド時に投影した軽量版です。完全版を起動時に取得しないため、オフライン利用も維持できます。
- 完全版を更新した場合は `node tools/build-runtime-master.mjs --write` で埋め込みを更新し、`node tools/build-runtime-master.mjs --check` と `node --test tests/*.test.mjs` で確認してください。
- 新しいUIが別のMaster項目を必要とするときは `lib/runtime-master-projection.mjs` へ明示的に追加してください。一括の起動時取得へ戻さないでください。
- UI上のネタバレ防止は従来どおりPlayer Stateの発見状況で判断し、未発見情報を新しく表示しません。

## 性能診断（v0.11.13〜）
- 設定 → 「性能診断を表示」で、ページ開始からの起動準備・タブ移動・画面描画・保存の経過時間を確認できます。
- タブ/描画/保存は直近40回を保持し、中央値・P95・最大時間を表示します。操作後は「計測値を更新」を押してください。
- 診断結果はクリップボードへコピーできます。個人のプレイヤーデータ、攻略・Master内容、端末ID等は含みません。
- 計測値はRAMにだけ存在し、保存・アップロードしません。アプリを再起動すると消えます。
- 起動時間の計測はPerformance APIによるページ開始〜IndexedDB読込完了であり、OSのホーム画面からの起動開始や実機の描画完了フレームを保証するものではありません。
- 計測が端末の応答速度へ与える影響は小さくなるよう設計していますが、実機の速度向上や完全な性能評価は別途確認します。


## カレンダー・作戦の使い勝手（v0.11.14〜）
- 日別カレンダーに祭りの概要と時間（受付時間と訪問時刻を区別）を表示します。元の日付算出は変更していません。イベントの確認先：GameWith（https://gamewith.jp/bokumono-grabaza/514615）、既存のバザール営業時間Master。
- 種・苗・菌の「育成中」は一覧と詳細の両方で強調します。登録済み `playerState.*.growing` と `growingCount` の読み取りのみで、新しい在庫概念は作りません。
- お願いはタイトルと依頼人を入力してから「🔍 お願いをMaster照合」を押します。候補をタップして確定する仕組みは使わず、依頼人名も手入力します。曖昧な照合では未知の候補を露出しません。
- お願いの達成条件は読み取り中心です。「進捗の数値」は入力・表示しませんが、既存JSONの進捗値は破棄しません。ゲーム内で報告が終わったら「完了」にします。
- `state.requests[].flavorText` は任意のゲーム内文章です。既存の `note` とは別に保存します。完全版Masterの128件に原文は現時点で未収録であり、確認の取れていない文章を創作しません。将来 `MASTER.requests[].flavorText` に典拠付きで追加した場合のみ自動表示可能です。
- 「やること」の並べ替えは☰ハンドルを上下に動かします（キーボードの↑↓にも対応）。未完了の `state.actions` の並び順だけ変更し、完了済みの位置とID・内容・紐付けを保持します。操作取り消しにも対応。

## 種管理・料理登録（v0.11.16〜）
- 種・苗・菌をタップすると「いまの記録」（品質・数・保管・育成）と栽培情報を先に表示します。入力欄は「✎ 記録を編集する」で開き、閲覧だけで閉じた場合には編集データの再保存を行いません（従来の「最近見た」履歴は保存されます）。
- 育成中はラベルで示しますが、一覧の行と詳細バナーの背景を緑にはしません。
- 「知った料理を登録」では、**既知の料理**だけ短い文字列でも候補に表示します。未知料理は正確に入力した場合、または4文字以上の接頭辞から全Master中1件へ絞れた場合のみ候補にします。未知料理の一覧閲覧はできません。候補をタップしただけでは登録せず、照合・登録ボタンで確定します。
- 「知っている候補」は `knownEntities` / `knownProcesses` / `knownRecipes` に基づく動的な既知情報であり、実在庫や所持数の証明ではありません。既知の料理・加工を登録すると関連する既知の食材も更新されます。ゲーム進行や外部Masterの更新を端末が自動検知する仕組みではありません。
