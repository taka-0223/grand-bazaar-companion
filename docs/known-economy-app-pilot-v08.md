# Known Economy v0.8 — App接続の試験画面と受け入れ条件

## 位置づけ

v0.7までに実Player State v7とMasterの既知情報を接続・監査し、未確認の在庫や売価を推定しないガードを整備した。v0.8は本番画面の全面統合**ではなく**、`economy-lab/index.html`で利用できる任意起動・読み取り専用の試験画面である。

App側の通常画面、`index.html`、`release.json`、Player State、保存関数は変更しない。比較画面には専用URLからアクセスする。**Service Workerのナビゲーション分岐だけ**を修正し、従来のホーム用オフラインキャッシュを保持しつつ、専用ページを誤ってホームへ差し替えない。既存の5タブや常時起動にボタン・計算負荷を増やさない。

## 起動と入力の流れ

1. **端末の記録を読む**、または端末に保存した**JSONバックアップを選択**する。公式バックアップの`{format,formatVersion,state}`を確認。旧・将来スキーマを自動移行しない。
2. 明示的な起動を受けて`createKnownEconomyLoader`が完全版Master (`data/board-master.full.v1.json`) を取得。ページの表示・モジュール読み込みだけではフルMasterを取得しない。
3. `listAppKnownEconomyDiscovery`から**既知品目**の選択肢を表示する。現行Masterの未発見品一覧にはアクセスしない。学習済み加工方法・料理に紐づいた設備だけが候補になり、所持/解放の事実は**利用者がチェックして確認**する。
4. 対象、比較可能時間（分）、基準売価・加工費0Gなどのシナリオ仮定を明示。使える設備/加工ルートをユーザーが確認する。**未指定の時間、設備、ルートを「0」や「使えない」とみなさない**。
5. 利用する既知経路について、在庫・売価・所持金・設備枠・目標/お願い用の資材競合を確認。不明なら結果を保留する。`requirements.have`や`seedCount`を収穫済み在庫として流用しない。
6. 入力チェックが通り、1件以上のルートを選んだ場合に限り`compareAppKnownEconomy`を実行。評価済みの上位4候補のみ参考表示する。

## 安全なデータ境界

- `readDevicePlayerState`: IndexedDBの**既存**DBが実在すると確認した場合のみ、`kv/state`をread-onlyトランザクションで読み取る。`indexedDB.databases()`未対応の場合は従来のlocalStorageミラーを読む。時刻の新しいものを選ぶ。**open時にDB新規作成・マイグレーションをしない**。
- JSONはFile APIでブラウザ内だけで解析。サーバーへのPOST、アップロード、URLクエリへのユーザー情報埋め込みを行わない。
- `knownEntities`などの明示的な登録情報からのみ候補を生成する。料理の未知材料・隠しレシピ・未解放品は表示しない。
- 入力はページを閉じると消える。**Player Stateへは一切反映しない**。現物数を手入力しても既存の種管理を上書きしない。
- 完全版Masterは試験ページでのみ遅延取得する。Service Workerはホームへの遷移のみ従来のキャッシュ優先、専用ページへの遷移はネットワーク優先＋取得成功後キャッシュへ変更。**初回オフライン利用は未保証**。通常アプリの保存・起動用Masterには影響しない。
- 更新時は`economy_rev`クエリパラメーターを更新して、キャッシュ済みの古いMasterを取り違えないようにする。

## 比較結果の意味

- `+75G`などは、確認された価格・時間・費用の**入力条件における「直接売却との差」**である。全農場の収益・実際のバザール販売枠・品質別最適解を保証しない。
- 同一品質での価格条件、加工できる回数、取り置きなどは、ゲーム内で確認して利用する必要がある。入力欄の価格は実売価格を自動取得したものではない。
- ルート未選択や比較材料不足の場合、**「直接売るべき」「直売が最善」とは表示しない**。
- 目標やお願いが存在する場合の確認チェックは、**競合しないと利用者自身が判断した**ことだけを表す。実在庫からの自動取り置きは行わない。正式Appへの統合時には個別数量での取り置きUXを追加検討する。

## 実プレイヤーバックアップからの条件整理（原本非公開）

2026-10-10のバックアップはPlayer State v7 / App v0.11.12で、既知品目・料理・加工はMasterに対応している。収穫済み現物の一般在庫と所持金はStateに保存されていない。小麦の`seedCount`などは種・加工中の個数であり、収穫済み小麦の証拠ではない。そこでUIでも**必ず別入力**にする。岩塩旧IDは確実な対応がないため暫定的に比較候補から除外する。

**この資料とリポジトリにはユーザーの実バックアップJSON、メモや在庫一覧は含めない。** 回帰テストは保存形式に準拠した合成レコードのみを使用。

## 試験画面への導線とService Worker

専用ページは`economy-lab/`。アプリ本体のナビゲーションからは未リンク。新Service Worker有効化前に古いキャッシュが稼働している端末では、設定のアプリ更新確認または再起動後に専用ページを開く。既存のAPP_VERSIONは0.11.12のまま。`tests/economy-lab-routing.test.mjs`でホームのオフライン動作、専用ページのネットワーク/キャッシュ動作、非GETの非介入をテストする。

## App本体へ昇格する条件

- 実機で「端末記録」「JSON選択」を確認し、**ゲーム機の実際の保有量と照合**する。
- 自分が未発見の名称・レシピ・経路がUI・エラー・順位・候補数に一切出ないことを確認する。
- 操作ミスから戻る際の手数を減らし、数字入力時もボトムシートのボタンが隠れない。
- キーボード表示/戻る操作/横スワイプ等、既存UI操作を壊さない。
- 比較起動前と比較後の通常PWA起動時間、描画遅延、保存時の応答、メモリ・オフライン状態を実機で比較する。
- 現物在庫・品質・バザール補正・個別取り置きが未対応であることをUI上で明確化する。
- アプリ内導線を追加する場合も、ホーム起動時に全Masterや計算器を読み込まない。
